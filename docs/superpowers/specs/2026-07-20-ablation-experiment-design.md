# 面向陪伴场景的情感支持对话系统消融实验设计

## 1. 实验目标

面向系统设计类毕业设计，验证各核心模块的功能收益与系统代价。实验不复用既有 `exp` 目录中的脚本、样本或结果；后续所有资产均放入新的独立实验目录。

## 2. 环境与原则

- 环境：长期运行的 Server A、Server B、MySQL、xiaoyun-server-lite 与客户端联调环境。
- 对照组：完整系统，启用策略层、分层记忆、用户画像、音乐情绪信号、句子级语音流水线和异步音频分析。
- 消融原则：每轮仅关闭一个目标模块或模块组，其余模型、提示词、样本、硬件和并发条件固定。
- 采样原则：每组预热后采集不少于 100 次请求；并发 1、5、10 分别测试。
- 统计原则：连续指标报告均值、标准差、P50、P95、P99 和相对变化；离散指标报告成功率或胜率。A/B 质量评分采用配对统计检验。

## 3. 独立目录设计

后续在仓库根目录创建 `ablation_experiments/`，与 `exp/` 并列，包含：

- `configs/`：每个实验组的开关配置快照。
- `datasets/`：新的对话、语音和音乐任务样本。
- `prompts/`：GPT 评审提示词和 JSON 输出约束。
- `scripts/`：执行、采集、评审、汇总和绘图脚本。
- `raw/`：不可修改的逐请求观测记录。
- `results/`：聚合指标、统计检验和图表。
- `reports/`：论文表格和案例分析素材。

## 4. D 系列：对话智能层

| 组别 | 配置 | 功能指标 | 性能指标 |
| --- | --- | --- | --- |
| D0 | 完整系统 | 全部基准 | 全部基准 |
| D1 | 关闭对话策略层 | 意图和风险识别、共情性、非说教性 | 策略耗时、端到端延迟 |
| D2 | 关闭稳定记忆与事件记忆注入 | 上下文连续性、未完话题跟进率、误召回率 | Prompt 长度、LLM 首 token 延迟 |
| D3 | 关闭用户画像与音乐信号注入 | 个性化匹配率、情绪假设正确率、偏好引用准确率 | Server B 调用时延、端到端延迟 |
| D4 | 关闭软确认机制 | 错误归因率、过度分析率、自然度 | 对话轮数、平均回复长度 |

评审维度为共情性、相关性、自然度、连续性、非说教感、安全边界和个性化匹配度，均采用 1 至 5 分。

## 5. V 系列：语音交互体验层

| 组别 | 配置 | 功能指标 | 性能指标 |
| --- | --- | --- | --- |
| V0 | 完整句子级流水线 | 语句完整率、语音连贯性、打断恢复成功率 | 首句语音延迟、全回复完成时间、句间间隔 |
| V1 | 关闭句子级流水线，完整文本后统一 TTS | GPT 流畅度、信息完整性 | 首句语音延迟、总时延 |
| V2 | 保留拆句，关闭并发 TTS | 语句顺序正确率、漏句率 | 句间 P95 间隔、队列等待时间 |
| V3 | 降低句子和音频任务队列上限 | 过载时回复完整率、降级正确率 | 高并发成功率、内存峰值、P95 延迟 |

关键指标：`T_first_audio`、`T_complete`、`Gap_p95`、`Completion_rate`。使用新建的短、中、长回复触发语料，在每个并发级别重复 30 次。

## 6. S 系列：异步服务与数据链路

| 组别 | 配置 | 功能指标 | 性能指标 |
| --- | --- | --- | --- |
| S0 | 完整异步链路与画像缓存 | 分析结果可用率、画像可用率、任务一致率 | 吞吐量、端到端时延、CPU、内存 |
| S1 | 请求链路同步等待音频分析 | 分析结果一致性 | 对话响应时延、超时率、并发成功率 |
| S2 | 关闭画像缓存 | 画像新鲜度、画像注入成功率 | 画像接口 P50/P95、数据库查询时延、总延迟 |
| S3 | 关闭音频情绪分析 | 情绪特征可用率、个性化匹配度 | 对话时延、资源占用变化 |
| S4 | 注入 Server A 延迟、Server B 超时或 MySQL 短暂不可用 | 降级回复正确率、恢复后任务一致率 | 错误率、恢复时间、P95 延迟 |

关键指标：`Task_enqueue_rate`、`Task_success_rate`、`Analysis_latency`、`Persona_hit_rate`、`Cache_hit_rate`、`WS_success_rate`、`CPU_peak` 和 `Memory_peak`。

## 7. GPT 评审协议

- GPT 仅用于评审，与系统生成回复的模型独立。
- 评审输入隐藏实验组、模块名称和生成来源。
- 每一对回复随机化 A/B 展示顺序，并额外执行反向顺序评审。
- 每个样本独立评审 3 次，使用均值作为最终分数。
- GPT 输出结构化 JSON：各维度分数、优胜回复、理由和异常标记。
- 保留完整提示词、模型版本、温度、时间戳和原始 JSON，保证可追溯。

## 8. 有效性控制

- 同一实验内固定模型版本、温度、系统提示词、机器资源和网络部署位置。
- 对话样本按情绪表达、求助、安静陪伴、音乐信号、未完话题和高风险边界分层。
- 性能实验剔除预热请求，记录失败和超时请求，不仅保留成功样本。
- 故障注入只影响测试请求；测试后等待队列清空，并核对 MySQL 中任务、分析结果、播放记录和画像数据一致性。
